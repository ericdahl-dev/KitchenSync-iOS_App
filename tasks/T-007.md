## Goal

The reboot-required settings, quarantined into their own sheet so nobody trips over one by
accident. Saving here POSTs the full form to `/save`, which persists to NVS **and reboots the
device** — mid-set, that is a destructive act, and the UI has to say so.

## Acceptance Criteria

- [ ] Sheet is seeded from `GET /config.json` (T-009 covers the 404 case)
- [ ] Edits the reboot-only settings: WiFi slots, `metronome` enable, `follow_beat` enable
- [ ] Save calls `postSave(_:wifiEdits:)`, never `postLive`
- [ ] An explicit confirmation before saving that names the consequence: **the device reboots
      and drops out of the Link session**
- [ ] Post-save, the device is shown as rebooting/unreachable until it comes back (leans on T-010)
- [ ] Three WiFi slots (`KS_WIFI_SLOTS`), each an SSID field plus an optional new password
- [ ] A slot with a saved password shows *that a password is set*, never the password itself
- [ ] Leaving a password field blank keeps the existing one — and the UI says so, because a blank
      field otherwise reads as "erase it"
- [ ] Written test-first per the /tdd rule

## Notes

**Passwords are write-only.** `GET /config.json` deliberately omits them, mirroring the device's
own web form, which won't echo a saved password back either. `WifiSlot` exposes only
`passwordIsSet`. New passwords ride in `WifiCredentialEdit`, and `saveFormFields` omits the
`wifi_pass` field entirely when the string is empty — that's `ks_config_set`'s documented no-op
for "keep current". So the empty-means-keep behaviour is already correct in the model layer; this
task is about making sure the *user* understands it.

`wifiEdits` is keyed by slot `id`, not array position. If the view filters or reorders the slots
before handing them over, keep the `id` — `saveFormFields` uses it to pick the `wifi_ssid`/
`wifi_ssid1`/`wifi_ssid2` suffix, and getting it wrong silently overwrites the wrong network.
