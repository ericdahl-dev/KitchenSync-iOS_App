## Goal

`GET /config.json` is newer than the fleet. It landed in P4-041 on 2026-07-14, so any unit
running firmware built before that date will 404 on it — while every other route keeps working
fine. Right now that failure has no story: config editing would just break, opaquely, on an
older device.

## Acceptance Criteria

- [ ] A 404 from `fetchConfig()` is distinguished from a real network failure
      (`KitchenSyncClientError.httpStatus(404)` vs. everything else)
- [ ] A device on old firmware still works for everything that doesn't need `/config.json`:
      status, transport, live edits, OTA
- [ ] The config/settings UI (T-006, T-007) explains *why* it's unavailable and points at the fix
      — update the firmware (T-008) — rather than showing an empty or broken form
- [ ] Written test-first per the /tdd rule: stub a 404 and assert the app stays usable

## Notes

This is the case for making OTA (T-008) reachable from a device that can't show its own config —
the way *out* of the degraded state is a firmware update, so don't gate the update sheet behind
a successful config fetch.

Worth deciding explicitly: do we let a user *blind-edit* config on old firmware by POSTing
`/save` with values we never read back? Almost certainly not — a full-form save with fabricated
defaults would clobber settings we couldn't see. Read-modify-write is not possible without the
read, so the honest answer is to disable the settings form and say so.
