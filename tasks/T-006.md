## Goal

One device's screen: live telemetry up top, the four output cards (T-003) below, and the
live-editable settings — the ones that apply instantly with no reboot.

## Acceptance Criteria

- [ ] Header shows live `/status`: bpm, peer count, playing, tick/phase health
- [ ] Four `OutputCardView`s (T-003), one per `KS_CLOCK_OUTPUTS`
- [ ] Live-editable controls dispatch `KsLiveEdit` cases through `postLive(_:)`:
      LED brightness/mode/fade/colors, metronome volume/voice/accent, clock-out enable,
      and the per-output cable/ppqn/phase/swing
- [ ] Reboot-only settings are NOT on this screen — they live behind the settings sheet (T-007)
- [ ] A toolbar route into the settings sheet (T-007) and the firmware sheet (T-008)
- [ ] Written test-first per the /tdd rule where there's logic to test

## Notes

**The split between this screen and T-007's sheet is the `KsLiveEdit` case list, exactly.**
If a control has a `KsLiveEdit` case, it belongs here and applies immediately. If it doesn't —
WiFi credentials, the `metronome` *enable* flag, the `follow_beat` *enable* flag — it is
reboot-only and belongs in the settings sheet. `/live` silently ignores those fields, so putting
one on this screen produces a control that appears to work and does nothing.

Note the trap: metronome *volume/voice/accent* are live, but metronome *enable* is not. Same for
`follow_beat`. The enum is the source of truth; check it rather than guessing from the field name.

Sliders should debounce — `/live` is a real HTTP POST per edit, and dragging a brightness slider
would otherwise fire dozens.
