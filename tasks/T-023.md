## Goal

**Discovery has no seam, so the list view model can't be tested with a fake — and a test has been
left reaching past the interface to compensate.** `DeviceListViewModel` news up its discovery
concretely, and `KitchenSyncDiscovery` news up `NWBrowser` concretely:

- `ViewModels/DeviceListViewModel.swift:35` — `private let discovery = KitchenSyncDiscovery()`
- `Discovery/KitchenSyncDiscovery.swift:38` — `NWBrowser(for: .bonjour(...))`

The tell is at `ViewModels/DeviceListViewModel.swift:98-108`: `merge(discovered:)` is left `internal`
"so a test can put a DISCOVERED device into the list without standing up Bonjour." The test reaches
*past* the interface because there is no discovery adapter to substitute. And the restart policy in
the glue — `.failed` → restart, a denial → deliberately do **not** restart
(`Discovery/KitchenSyncDiscovery.swift:44-52, 78-85`) — has **no test at all**, because `NWBrowser`
is hard-wired.

Introduce a small interface (a `DeviceSource`: emits hostname sets + `DiscoveryStatus`) with two
adapters — the real `NWBrowser` one and an in-memory one for tests. Two adapters justify the seam.

## Acceptance Criteria

- [ ] A `DeviceSource` interface exists: it publishes discovered hostnames and status changes
- [ ] `DeviceListViewModel` takes a `DeviceSource` (injected, defaulting to the `NWBrowser` adapter)
      instead of constructing `KitchenSyncDiscovery()` directly
- [ ] `merge(discovered:)` can return to `private` — tests drive discovery through the in-memory
      adapter, not through an internal method
- [ ] The restart policy is now testable and tested: a `.failed` browser state triggers a restart; a
      permission denial does **not** (it would just be refused again — see the doc comment)
- [ ] `DeviceMatch` stays exactly where it is — it is already a pure, tested decision; this task does
      not touch the matcher, only the glue's dependency shape
- [ ] Written test-first per the /tdd rule

## Notes

**Don't over-fire on this one.** The pure decision (`DeviceMatch.isKitchenSync`) and the status
mapping (`DiscoveryStatus(browserState:)`) are already correctly extracted and tested — the latter
is a rare case where the test doesn't have to reach past the interface. This task is strictly about
(a) the view model's hard-wired discovery dependency and (b) the untested restart *policy* in the
glue. Everything behind `DeviceMatch` is fine.

Real seam, not hypothetical: the second adapter (in-memory) is what makes tests honest, and the
`NWBrowser` adapter is the production one — two adapters, so the seam earns its place rather than
being speculative indirection.

This intersects T-019 (fall back to resolved IP): the same `NWBrowser`/`NWConnection` resolution
path is where the IP and the future TXT record get read. If T-019 lands first, fold its resolution
into the same adapter rather than adding a second discovery path.
