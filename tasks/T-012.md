## Goal

Make firmware/app drift on the live-vs-reboot split a **test failure**, not a stage failure.

The split is `KsLiveEdit`'s case list and nothing else. Today that is enforced by a doc comment.
A doc comment does not fail CI.

## Acceptance Criteria

- [ ] Declare an explicit `RebootRequired` key list (WiFi keys, `metronome`, `follow_beat`)
- [ ] Test partitions the key set of `KsConfig.saveFormFields(wifiEdits:)` into exactly two
      disjoint sets: keys `KsLiveEdit` can emit, and `RebootRequired`
- [ ] **Every key lands in exactly one.** Test FAILS if a key is in both, or in neither
- [ ] A new field added to `saveFormFields` with no classification fails the test
- [ ] Test names the consequence in its failure message — an unclassified field is a control that
      might silently reboot a device mid-set

## Notes

The trap, verified in firmware: `metro_accent` is live (`ks_web.cpp:199`, `class="live"`) but
`metronome` **enable** is not (`ks_web.cpp:196`, no class). Same for `follow_beat`
(`ks_web.cpp:209`). `led` enable IS live. Field names give you no signal — only the enum does.

The web UI has this same distinction and renders it as an invisible CSS class. Our advantage is
that we can make it a type error and a test failure instead.

If firmware later makes a field live-safe, this test is what tells you — instead of a user
finding out when the box reboots during a set.

Pairs with the `KSLiveControl` wrapper (see the design direction, §6): the wrapper makes the
wrong thing unconstructable, the test makes drift loud. Belt and braces; the two catch different
mistakes.

Ref: `docs/design/2026-07-14-view-layer-design-direction.md` §6.
