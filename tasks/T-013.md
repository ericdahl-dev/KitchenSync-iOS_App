## Goal

Transport without unlocking the phone.

The web UI has keyboard shortcuts (`.kbd`) for exactly this need — hit transport without hunting a
control. On a phone the equivalent is a Live Activity / Dynamic Island: the four launch states
visible on the lock screen, tappable.

## Acceptance Criteria

- [ ] ActivityKit Live Activity, started when a device is being actively controlled
- [ ] Shows all four outputs' `TransportLaunchState` (stopped / armed / running)
- [ ] Armed state blinks at beat rate, same generator as `TransportButton` (T-003)
- [ ] Dynamic Island compact + expanded presentations
- [ ] Tap → stop (Stop is immediate and always safe; see below)
- [ ] Written test-first per the /tdd rule where there is logic to test

## Notes

**Stop is safe to expose on a lock screen. Play may not be.** Stop is immediate and unambiguous.
Play is quantized and arms — a stray lock-screen tap that arms an output which then fires at the
next bar line, unattended, is a bad outcome on stage. Start with Stop only; revisit Play.

Live Activity updates need a push or a foreground process. Our poll loop is foreground-only, so
work out the update path before committing to this — it may need push-token updates from a
companion, which is a much bigger lift than it looks. **Scope this properly before starting.**

Low priority: nice-to-have, and it depends on the transport UI (T-003) and detail screen (T-006)
being settled first.
