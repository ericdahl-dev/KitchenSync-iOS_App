## Goal

**One firmware fact — the form-field wire grammar — is copied into four places, and nothing but a
test keeps the copies aligned.** The `KsLiveEdit`-case ↔ wire-key ↔ config-field relationship is a
single thing (it comes from `ks_config.c`'s `ks_config_set()`), but it has no single owner:

- `Models/KsConfig.swift:90-97` — `CodingKeys` (decode side)
- `Models/KsConfig.swift:210-262` — `saveFormFields` (save-encode) + `boolField`/`colorField`
- `Models/KsLiveEdit.swift:32-54` — `formField` (live-encode) + `boolValue`/`colorValue`
- `Models/KsConfig.swift:276-298` — `apply(_:)` (fold an accepted edit back in)

The value encoders are byte-for-byte duplicated:

```swift
// KsLiveEdit.swift:54
private func colorValue(_ v: UInt32) -> String { String(format: "#%06X", v & 0xFFFFFF) }
// KsConfig.swift:260-262
fileprivate static func colorField(_ value: UInt32) -> String { String(format: "#%06X", value & 0xFFFFFF) }
```

and `boolValue` / `boolField` both return `v ? "1" : "0"`. The keys themselves (`led_beat`,
`clk\(i)_phase`, …) appear in both `formField` and `saveFormFields`.

This is a **shallow seam with no locality**: the grammar is a deep fact spread thin across four
modules. Deepen it into one module that owns the key strings and the value encoders, keyed by
`KsLiveEdit` case, so decode / save / live / apply all read from one place.

## Acceptance Criteria

- [ ] A single module owns each field's wire key and its value encoding (bool, color, int)
- [ ] `saveFormFields`, `KsLiveEdit.formField` and `apply(_:)` all reference that one source — no
      duplicated key literals, no second copy of the `#%06X` / `"1"/"0"` encoders
- [ ] The live-vs-reboot partition is **derived from the types**, not reconstructed by a test that
      reaches across three interfaces (see `LiveRebootPartitionTests`, and the Notes below)
- [ ] `LiveRebootPartitionTests` still passes — but ideally it now asserts a property the types
      already guarantee, rather than being the only thing that guarantees it
- [ ] Every existing decode/encode test still passes against fixtures built from real firmware
      `snprintf` / `ks_config_set()` output
- [ ] Written test-first per the /tdd rule

## Notes

**This touches the single most important rule in the codebase — read it before starting.** The
split between live-editable and reboot-required IS the `KsLiveEdit` case list (CLAUDE.md, and the
codebase-memory ADR). The three defenses must survive untouched:

1. Every control on `DeviceDetailView` routes through a `KsLiveEdit` case — that screen *cannot*
   reboot the device.
2. Reboot-required settings live only in `DeviceSettingsSheet`, behind the consequence band.
3. `LiveRebootPartitionTests` asserts every `saveFormFields` key is either live-editable or in
   `KsConfig.rebootRequiredFormKeys` — never both, never neither.

This deepening **strengthens** that invariant (moves the guarantee from a test into the types); it
does **not** reopen the ADR. If at any point the refactor would let a reboot-only field become
routable through `/live`, stop — that is the exact failure the current design prevents by hand.

The trap to preserve: `metro_accent`, `metro_vol`, `metro_voice` are live, but metronome *enable*
is not; `led` enable is live but `follow_beat` enable is not. The grammar module must not flatten
that distinction — it is not guessable from the field names.

Source of this task: architecture review 2026-07-14 (candidate 01, the top recommendation). It is
also the root of T-021's duplication — the same "spread a decision across call sites" shape.
