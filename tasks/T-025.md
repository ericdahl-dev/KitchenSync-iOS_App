## Why

Cross-repo drift surfaced by the 2026-07 architecture initiative
(`docs/architecture/firmware-contract.md`).

`T-011` was filed on the premise that the **firmware advertises no distinguishing TXT
record**, so `KitchenSyncDiscovery` must fall back to a hostname prefix that can
false-positive. That premise is now stale: the firmware **does** emit a `dev`/`model`/
`target`/`fw` TXT record — `link-devices/KitchenSync/main/wifi_link.c` (ESP-037) and the
X32Link equivalent (which publishes `dev=x32link` so this app does not adopt it).

But this app still behaves and reads as if TXT is absent:
- Code comments in `KitchenSyncDiscovery.swift` state TXT is *"nil for every unit in the
  field today,"* which is no longer true for up-to-date firmware.
- `DeviceMatch` already *prefers* TXT when present and only falls back to the hostname
  prefix — so the logic is ready; what is stale is the assumption, the comments, and the
  lack of verification against real firmware.

The result is a documented but unverified skew between the two repos.

## Acceptance Criteria

- [ ] Verify against a real unit (via `link-devices/tools/linkcli` on the bench) that the
      `dev=kitchensync` TXT record arrives and `DeviceMatch` selects on it — the first
      real-Bonjour verification (closes the "never seen a live responder" gap for discovery).
- [ ] Update the stale `KitchenSyncDiscovery.swift` comments to reflect that current
      firmware emits the TXT record; keep the hostname fallback only for older units and
      say so.
- [ ] Confirm a non-KitchenSync host named `kitchensync-*` is rejected when a genuine unit
      with `dev=x32link` (or no TXT) is on the same LAN.
- [ ] Reconcile with `link-devices` ESP-031 (exact identification / chip target): if a
      service subtype lands there, prefer it; otherwise `dev=` is sufficient.
- [ ] Update `T-011` status once firmware advertisement is confirmed shipped (its fix has
      effectively landed via ESP-037).

## Notes

Firmware side is **not** the blocker anymore — this is an iOS verification + cleanup task.
Small, but it is the one live piece of contract drift the architecture docs flag, and it
turns discovery from a hostname heuristic into an exact match in the field.

The durable fix for this whole class of hand-mirrored-contract drift is a shared
`ks-protocol` schema — see `link-devices/docs/architecture/repository-roadmap.md` (step 4),
gated on the contract churning enough to justify it. Not that yet; this is the cheap
point fix.
